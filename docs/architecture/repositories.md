# What it takes to run jaen, and where each piece lives

Owner (Florian), 2026-09-07: "is everything that's needed to run jaen in
the jaenjs org, like osg and so on? If not it would be nice to have all
the necessary repos."

| Piece                                                                                                         | Repository                                                                                                                                                   | State on 2026-09-07                                                                                                                                                                                        |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| jaen itself: `jaen`, `gatsby-plugin-jaen`, `gatsby-source-jaen`, the field and app plugins, the agent package | `jaenjs/jaen`                                                                                                                                                | the estate's 127 commits since the pin `b2dd711` pushed as `feat/estate-2026-09` this evening, they had lived on one machine only                                                                          |
| The storage gateway                                                                                           | `jaenjs/open-storage-gateway` (private)                                                                                                                      | the private storage work of `private-storage.md` goes there as a branch and a pull request                                                                                                                 |
| The identity façade, one typed GraphQL API over Zitadel, the auth module every jaen service copies            | `jaenjs/jaen-idm` (private, created this evening as `idm` and renamed from the deployed façade's `main`, lineage `netsnek/iam` and `kleberbaum/zitadel-gql`) | the deployed `idm.limosen.at` and `idm.booklimo.at` come from this code                                                                                                                                    |
| The jaen agent, the service that keeps a site's draft in its repository                                       | `jaenjs/jaen-agent`                                                                                                                                          | a Pylon prototype from June 2025 stands there; the package built in the monorepo (`packages/jaen-agent`, `draft-state.md`) is published into that repository on top of its history and deployed from there |
| Mail                                                                                                          | `netsnek/emailwerk` (`jaenjs/mailpress` is its old name)                                                                                                     | optional, only `gatsby-jaen-emailwerk` needs it                                                                                                                                                            |
| The identity server                                                                                           | Zitadel, `accounts.netsnek.com`                                                                                                                              | external, one instance for the estate, one organisation per site                                                                                                                                           |

Everything a site build needs (GitHub Actions in the site's repository,
the gateway token, the plugin options) is described in the site
template and in `private-storage.md`.
